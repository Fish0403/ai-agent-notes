# Agent Memory Techniques 项目笔记

> 来源: [NirDiamant/Agent_Memory_Techniques](https://github.com/NirDiamant/Agent_Memory_Techniques)
> 30 个可运行的 Jupyter Notebook，覆盖 LLM Agent 的全部主流记忆模式

## Agent Memory 两大分类

- **短期记忆**：当前任务或会话的上下文（Working Memory 或 Session Memory）
- **长期记忆**：跨任务或会话的经验与知识（Persistent Memory）

![Agent Memory Taxonomy](Agent_Memory_Techniques/images/taxonomy.png)

## 为什么需要 Agent Memory

大多数 AI Agent 的现状：每次对话都是陌生人。没有记忆，Agent 无法跨会话保持上下文、无法从历史交互中学习、无法与用户建立持久关系。

Agent Memory 就是让 LLM Agent 在 **多轮、多会话、多任务** 之间记住信息的一整套技术。

## 六大类 30 种技术

### 1. 短期记忆 (Short-term) — 技术 01-05

单次对话内的上下文管理。

| # | 技术 | 核心思路 |
|---|------|---------|
| 01 | Conversation Buffer | 完整保存对话原文，最简单，其他技术的基础 |
| 02 | Sliding Window | 只保留最近 N 条消息，限制大小但保留近期内容 |
| 03 | Summary Memory | 用模型把旧对话压缩成摘要，保留语义但丢弃原文 |
| 04 | Summary Buffer | 旧消息压缩成摘要 + 近期消息保留原文，两者兼得 |
| 05 | Token Buffer | 按 token 预算裁剪历史，优先丢弃最旧的消息 |

### 2. 长期记忆 (Long-term) — 技术 06-11

跨会话、跨用户的持久化存储。

| # | 技术 | 核心思路 |
|---|------|---------|
| 06 | Vector Store | 把消息转成向量，后续按语义相似度检索 |
| 07 | Entity Memory | 抽取并追踪实体（人物、项目、偏好），持续更新 |
| 08 | Knowledge Graph | 构建实体关系图，通过图遍历进行推理 |
| 09 | Episodic Memory | 存储完整的交互事件（含时间地点），回答"什么时候发生了什么" |
| 10 | Semantic Memory | 从交互中提取通用事实，与原始事件分离存储 |
| 11 | Procedural Memory | 捕获"怎么做"的流程知识（workflow、操作步骤） |

### 3. 认知架构 (Cognitive) — 技术 12-19

借鉴人类记忆机制的模式。

| # | 技术 | 核心思路 |
|---|------|---------|
| 12 | Working Memory | 管理有限注意力，动态优先级、置顶、驱逐上下文 |
| 13 | Hierarchical Layers | 热/温/冷分层存储，随时间升降级 |
| 14 | Consolidation | 合并、去重、强化记忆，类似大脑睡眠时的记忆整合 |
| 15 | Compaction | 用摘要/实体抽取/蒸馏压缩存储，节省空间和 token |
| 16 | Self-Reflection | Agent 回顾自身行为，记录经验教训供下次使用 |
| 17 | Memory Routing | 根据内容类型和意图，路由到正确的记忆存储读/写 |
| 18 | Temporal Memory | 给记忆附加时间戳，检索时考虑时间权重 |
| 19 | Forgetting & Decay | 主动遗忘：基于衰减、访问次数、相关性进行剪枝 |

### 4. 检索与多 Agent (Retrieval & Multi-Agent) — 技术 20-23

| # | 技术 | 核心思路 |
|---|------|---------|
| 20 | Retrieval Patterns | 对比多种检索策略：语义搜索、时效性、混合打分、多样性、重排序 |
| 21 | Cross-Session | 跨会话保存/恢复 Agent 状态，用户可以无缝续接 |
| 22 | Multi-Agent Shared | 多 Agent 团队的共享存储、消息传递、一致性协议 |
| 23 | Memory as Tools | 把记忆操作暴露为工具（save/search/forget），Agent 可自主调用 |

### 5. 框架与平台 — 技术 24-27

| # | 技术 | 核心思路 |
|---|------|---------|
| 24 | Graphiti | Zep 出品，从对话构建时间感知的知识图谱 |
| 25 | Mem0 | 托管式记忆层，自动提取/存储/获取用户级记忆 |
| 26 | Letta (MemGPT) | 自编辑记忆，内/外独白架构，记忆压力管理 |
| 27 | Zep | 对话分类、实体抽取、时间感知图谱，面向生产 |

### 6. 评估与生产 — 技术 28-30

| # | 技术 | 核心思路 |
|---|------|---------|
| 28 | Evaluation | 检索精度/召回率、过时检测、矛盾检测、用户满意度 |
| 29 | LoCoMo Benchmarks | 用 LoCoMo/LongMemEval 评测长对话记忆表现 |
| 30 | Production Patterns | 缓存、TTL、分片、备份、GDPR、可观测性 |

## 关键概念速查

| 概念 | 解释 |
|------|------|
| Context Window | LLM 单次能处理的最大 token 数，是所有记忆技术的约束条件 |
| Vector Store | 将文本嵌入为向量并存储，支持相似度检索的数据库 |
| Knowledge Graph | 以 (实体-关系-实体) 三元组存储知识，支持图遍历推理 |
| Episodic vs Semantic | 情景记忆记"发生了什么"，语义记忆记"知道什么" |
| Memory Consolidation | 从短期到长期的记忆整合过程，去重、合并、强化 |
| Memory Decay | 记忆随时间衰减，访问频率高的记忆保持更久 |
